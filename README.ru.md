# hlds-run

**[English](https://github.com/Nord1cWarr1or/hlds-run/blob/main/README.md) | Русский**

hlds-run — краш-диагностическая обёртка для выделенного сервера Half-Life (`hlds_linux`) на bash. Запускает сервер на pty, зеркалирует его консоль оператору и в файл захвата, перезапускает после крашей под защитой от crash-loop, а на каждый краш пишет полный отчёт: состояние системы, последние 100 строк консоли и GDB-анализ core-дампа. Drop-in замена оригинального Valve `hlds_run` (сборки 10211 и новее).

## Требования

- Linux, bash 4+
- `util-linux` `script` ≥ 2.32 — для захвата консоли; без него обёртка уходит в обычный tty с предупреждением (`--output-limit` применяется, если установленная `script` его поддерживает)
- `gdb` — только для GDB-секции crash-отчётов
- `coredumpctl` — только если `kernel.core_pattern` — pipe-handler (systemd-coredump)
- `file` — для проверки, что core-дамп — настоящий ELF-core; при отсутствии выполняется только проверка по времени, и отчёт об этом сообщает
- `elfutils` (`eu-stack`) — опционально: добавляет в crash-отчёты реестр Build-ID модулей; без него секция пропускается

Проверено на Debian 11 (glibc 2.31), Debian 13 (glibc 2.44) и Arch Linux — на реальных серверах.

## Установка

Скопируйте скрипт в корень сервера — каталог, где лежит `hlds_linux`, — и сделайте исполняемым:

```bash
cp hlds_run /path/to/serverfiles/ && chmod +x /path/to/serverfiles/hlds_run
```

Другие файлы не нужны; вспомогательные создаются на время работы и удаляются после.

## Быстрый старт

```bash
./hlds_run -game cstrike -debug +map de_dust2
```

Обёртка запускается из корня сервера. Сессия «максимальный радар» — отчёты, дампы, проверка кучи и заливка памяти одновременно:

```bash
./hlds_run -game cstrike -debug -malloc-check -malloc-perturb +map de_dust2
```

## Использование

Скриптовые аргументы (серверу не передаются):

| Аргумент | Действие | По умолчанию |
|----------|--------|---------|
| `-debug` | Core-дампы + полный отчёт на каждый краш; кучу не трогает | выключено |
| `-malloc-check` | Проверка кучи glibc: `MALLOC_CHECK_=3` + preload `libc_malloc_debug` (см. «Heap-отладка») | выключено |
| `-malloc-perturb` | Заливка аллокаций: `MALLOC_PERTURB_=170` (см. «Heap-отладка») | выключено |
| `-debuginfod` | Разрешить GDB подтягивать debug-символы системных библиотек при анализе (сеть; URL — из настроек gdb, переопределяется через `DEBUGINFOD_URLS`) | выключено |
| `-norestart` | Без рестарт-цикла; код выхода сервера пробрасывается | рестарт включён |
| `-timeout N` | Задержка между рестартами, секунд (целое ≥ 1) | 10 |
| `-binary <path>` | Другой бинарник сервера | `./hlds_linux` |
| `-game <game>` | Тип игры; проверяется существование каталога | `valve` |

Всё остальное передаётся серверу без изменений — как у Valve `hlds_run`.

## Настройка

Регулируемые константы живут в шапке скрипта:

| Константа | Смысл | По умолчанию |
|----------|---------|---------|
| `TIMEOUT` | Задержка рестарта, если `-timeout` не задан | `10` |
| `STREAK_LIMIT` | Быстрых крашей подряд перед остановкой обёртки | `5` |
| `HEALTHY_UPTIME` | Аптайм, сбрасывающий счётчик крашей, секунд | `300` |
| `GDB` | Бинарник gdb для анализа отчётов | `gdb` |
| `GAME` / `HL` | Фолбэки для `-game` / `-binary` | `valve` / `./hlds_linux` |

## Рестарт-цикл

После краша сервер перезапускается с задержкой `-timeout`. Защита от crash-loop останавливает обёртку после `STREAK_LIMIT` крашей подряд, где каждый запуск прожил меньше `HEALTHY_UPTIME` секунд («Crash-loop detected»). Единичный краш после долгого аптайма сбрасывает счётчик. Чистый выход (код 0, Ctrl+C/SIGINT, SIGTERM — штатная остановка systemd) завершает цикл без отчёта.

## Crash-отчёт

Пишется на каждый краш в `crash_report_<дата>.txt` в корне сервера (в имени — миллисекунды, чтобы два краша в одну миллисекунду не перезаписали друг друга). Состав:

- код выхода, имя сигнала (`128+N` → SIGSEGV/SIGABRT/…), полная строка запуска
- состояние системы: ядро, load average, память, swap, диски, топ процессов по CPU и RSS, TCP/UDP-сокеты, последние 50 строк ядра (`dmesg`; при ограничённом dmesg — `journalctl -k` через доступ к журналу, например группу `adm`; шум отфильтрован, недоступные секции честно помечены)
- окружение движка по явному allowlist (`LD_LIBRARY_PATH`, `LD_PRELOAD`, `MALLOC_CHECK_`, `MALLOC_PERTURB_`, `TERM`, `HOME`); `STEAM_*` и `PATH` в отчёт не попадают. Файл создаётся с правами 600 — права выставляются до записи, не после
- md5-суммы: бинарник сервера, все `.so` из корня сервера и из `<game>/dlls` — заметна подмена бинарников или модов
- настройки core-дампа: `ulimit -c`, `kernel.core_pattern`, `kernel.core_uses_pid` (при 1 ядро дописывает `.PID` к имени дампа)
- последние 100 строк stdout+stderr сервера, очищенные от pty `\r`, ANSI-кодов и аннотаций `script`
- GDB-анализ дампа одним прогоном (`-nx`, без пользовательского `~/.gdbinit`), C++-значения печатаются в красивом виде, разбитый на подписанные секции — `Stacktrace` (`thread apply all bt full`), `Registers and frame info`, `Stack memory at $sp` (16 слов вокруг указателя стека), `Disassembly` (32 инструкции перед `$pc`), `Memory mappings`, `Shared libraries`. Известный шум gdb отфильтрован (`No symbol table info available`, предупреждения xstate, предупреждения об удалённых `/dev/shm`-маппингах, перекличка `[New LWP]`, строки регистров `k0-k7`); стрипнутые кадры `?? ()` остаются — это и есть backtrace
- проход elfutils перед GDB: `eu-stack -l` записывает Build-ID каждого загруженного модуля — единственную идентификацию, выживающую при strip (позволяет после краша сопоставить точные версии библиотек). Секция пропускается, если `eu-stack` отсутствует, и честно помечается пропущенной, если тот не смог прочитать дамп
- `-debuginfod` (opt-in): при анализе GDB может скачивать debug-символы системных библиотек с серверов debuginfod — осмысленные имена кадров libc и компании вместо сырых адресов. Цена: доступ в сеть и задержки, build-id ваших библиотек уходят на эти серверы; при gdb без поддержки — игнорируется с предупреждением на старте

## Core-дампы

Без `-debug` core-дампы и отчёты не создаются; поведение не меняется, heap-layout включительно. То же верно и под `-debug`: наблюдаемость кучу не трогает — её меняют только явные `-malloc-check` / `-malloc-perturb`.

С `-debug`:

- `ulimit -c unlimited` (с предупреждением, если лимит не поднялся — контейнер или сервисные ограничения)
- после анализа дамп переименовывается в `crash_core.<дата>.dmp`; дампы ротируются, остаются 3 самых свежих
- если `kernel.core_pattern` — pipe-handler (настроен systemd-coredump, файла на диске нет), свежие дампы экспортируются через `coredumpctl dump hlds_linux` (до 5 попыток с паузой — systemd обрабатывает дампы асинхронно), после анализа удаляются
- анализируются только дампы, которых не существовало на момент старта сервера (отслеживание по device:inode) и прошедшие проверку ELF-core (`file`); `core*` от прежнего краша или случайный `core_*.txt` игнорируются с предупреждением (то же ограничение действует и для `coredumpctl`)

## Heap-отладка (opt-in)

Флаги `-malloc-check` и `-malloc-perturb` включают отладочный malloc glibc. `-debug` кучу не трогает: отчёты и дампы можно снимать, не меняя поведение сервера. Оба флага добавляют накладные расходы и перестраивают кучу — включайте их на сессию диагностики, не на постоянку.

- `-malloc-check` — `MALLOC_CHECK_=3`, строгая проверка кучи glibc: порча heap даёт громкий `abort` вместо тихих последствий. На glibc ≥ 2.34 (Debian 12+, Arch, Ubuntu 22+) работает только с предзагрузкой `libc_malloc_debug.so` — обёртка находит её через `ldconfig` (32-битную, под бинарник сервера) и передаёт как `LD_PRELOAD` только серверному процессу (через launcher/`env`; хелперы обёртки preload не видят — нет шума `wrong ELF class` от 64-битных утилит); на старых glibc (Debian 11, CentOS) переменная работает без preload. **Отладочный malloc перестраивает кучу:** layout-чувствительная порча срабатывает в других местах, а в худшем случае исчезает вовсе (проверено на Debian 13: краши `SteamGameServer_Init` пропадали под preload). Краш, воспроизводящийся без `-malloc-check`, но не с ним, — layout-зависимый, и это само по себе зацепка
- `-malloc-perturb` — `MALLOC_PERTURB_=170`: свежие аллокации заливаются байтом 0xAA, освобождённая память — байтом ~0xAA (0x55). Заставляет use-after-free срабатывать почти сразу; добавляет ощутимую нагрузку на каждый malloc/free. Работает на любой glibc, preload не нужен

Свой `LD_PRELOAD` оператора (например, из systemd-юнита) не вырезается ни в каком режиме: он снимается с окружения обёртки (чтобы 64-битные хелперы не шумели) и передаётся серверу — вместе с heap-debug библиотекой, если включён `-malloc-check`; в лог пишется `Operator LD_PRELOAD passed to the server: …`. Если значение совпадает с найденной heap-debug библиотекой, дубль не создаётся.

## Захват консоли

По умолчанию сервер работает на pty через `script`: живой вывод идёт оператору, копия пишется в скрытый typescript внутри приватного временного каталога этого запуска (`mktemp -d`, права 700, под `TMPDIR` или `/tmp`; лимит 200 МБ `--output-limit` страхует от спамящей консоли; при достижении лимита `script` прекращает запись, а отчёт помечает хвост как возможно устаревший — он заморожен на момент обрезки, не краша), откуда отчёт берёт последние 100 строк обоих потоков. Команда сервера передаётся `script` через временный launcher-файл с шебангом `#!/bin/bash` — аргументы всегда разбирает bash, а не `$SHELL` (dash, fish и другие исказили бы кавычки и кириллицу). `script -e` сохраняет код выхода сервера. Без `script` — fallback в обычный tty с предупреждением. Пользовательских опций захвата нет — решение осознанное.

Перед запуском обёртка создаёт приватный каталог запуска под `TMPDIR` (или `/tmp`). Недоступный `TMPDIR` не останавливает сервер: захват отключается с предупреждением, и обёртка продолжает работу в plain-tty режиме (каталог сервера для захвата не пишется вовсе). В plain-tty режиме приватный каталог не создаётся, и `TMPDIR` не нужен.

Гигиена остатков: приватный каталог запуска удаляется после снятия хвоста, при любом выходе обёртки — и при смерти сессии (SIGHUP, закрытое окно screen/SSH). Смерти, которые трапом не поймать (`kill -9`, сбой питания), закрываются на следующем старте: приватные каталоги старше часа подметаются из `TMPDIR`.

## Файлы и артефакты

| Файл | Когда создаётся | Судьба |
|------|-----------------|--------|
| приватный каталог `hlds-run.XXXXXX` | каждый запуск обёртки | содержит launcher и захват консоли; удаляется EXIT-трапом, права каталога 700 |
| `crash_report_<дата>.txt` | каждый краш | копится, без ротации — так задумано |
| `crash_core.<дата>.dmp` | каждый разобранный краш | ротация, остаются 3 самых свежих |

Читает: бинарник и библиотеки сервера (md5-суммы), `/proc`, core-дампы. Значения `STEAM_*` и `PATH` нигде не записываются.

## Преимущества перед оригиналом

- **Полноценные crash-отчёты** вместо трёх команд (`bt`, `info locals`, `frame`) в общий `debug.log`: сигнал и код выхода, состояние системы (память, swap, диски, load, dmesg), окружение движка, md5-суммы бинарника и всех `.so`, настройки core-дампа, хвост консоли, полный GDB-разбор (`thread apply all bt full`, регистры, дизассемблирование вокруг `$pc`, mappings, shared libraries)
- **Один отчёт на каждый краш** (`crash_report_<дата>.txt`) — оригинал дописывает всё в один растущий `debug.log`
- **Захват консоли через pty**: оператор видит консоль живьём, отчёт получает последние 100 строк stdout+stderr (с чисткой `\r` и ANSI-кодов) — в оригинале консоль вообще не захватывается
- **systemd-coredump**: при `core_pattern` — pipe-handler дамп экспортируется через `coredumpctl`; оригинал знает только дампы-файлы на диске
- **Управление core-дампами**: переименование после анализа и ротация (3 свежих) — оригинал за дампами не следит вовсе
- **Защита от crash-loop**: остановка после серии быстрых падений; в оригинале рестарт бесконечен
- **Opt-in диагностика кучи**: `-debug` поднимает `ulimit -c unlimited` (в оригинале — 2000 блоков), не трогая кучу; флаги `-malloc-check`/`-malloc-perturb` включают проверку кучи отдельно — наблюдаемость не смешана с изменением поведения, а порча кучи даёт громкий abort только когда оператор этого попросил
- **Расшифровка сигнала** в отчёте (exit 139 → SIGSEGV и т.д.)
- **Строгий разбор аргументов**: скриптовые флаги никогда не утекают серверу; флаг без значения или нечисловой `-timeout` — ошибка, а не тихо искажённая командная строка, как в оригинале
- **Честный код выхода сервера** (через `script -e`); у части старых обёрток всегда выход 0

## Отличия от оригинала Valve hlds_run (10211)

Ядро — разбор аргументов, запуск, рестарт-цикл — совместимы. Не перенесено (устаревшая обвязка Valve):

- `-pidfile`, `-gdb`, `-debuglog`; `-debuglog` заменён отдельными файлами `crash_report_*.txt` (по одному на каждый краш)
- `-autoupdate`, `-steamerr`, `-beta` и переменная `$FORCE` (автообновление через steamcmd) — нет; обновляйте сервер отдельно, средствами SteamCMD или LinuxGSM
- `-ignoresigint`, `-notrap` — в самой сборке 10211 мертвы (обработчик trap закомментирован), не переносились
- `-help` отсутствует; вместо него — этот README

В оригинале диагностика крашей сводится к команде `bt`, записываемой в общий `debug.log`; здесь — полноценный отчёт с состоянием системы на каждый краш.
